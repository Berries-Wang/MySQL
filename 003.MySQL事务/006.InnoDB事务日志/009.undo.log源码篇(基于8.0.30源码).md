## 2. 分配：回滚段 → undo segment → undo log
&nbsp;&nbsp;undo 存放在 **undo 表空间**的回滚段（rseg）中。每个读写事务第一次修改时，从 rseg 分配（或复用）一个 undo log：
```cpp
// trx/trx0undo.cc:1687  为事务的 insert/update 各分配一个 undo log
dberr_t trx_undo_assign_undo(...)
//   ├─ :1752 trx_undo_reuse_cached —— 优先复用已提交事务腾出的缓存页 (定义 :1607)
//   ├─ :1757 trx_undo_create —— 无可复用时新建 (定义 :1548, 内部经 :390 trx_undo_seg_create 建 segment;
//   │     页不够时 :920 trx_undo_add_page 扩展)
//   └─ :1763/:1767 挂入 rseg 的 insert_undo_list / update_undo_list
```
```
undo 表空间
 └─ rollback segment (rseg, trx0rseg.cc)
     └─ undo segment (若干页, 含 1 个 undo 页头页 + 日志页)
         ├─ insert undo log  (INSERT 产生, 提交即释放, 只用于回滚)
         └─ update undo log  (UPDATE/DELETE 产生, 提交后挂 history list
                              ↳ 还要供 MVCC 读旧版本, 等 purge 才能删)
```
- undo 的「写 undo 本身也记 redo」（否则恢复后 undo 丢了就没法回滚/MVCC）——概念篇 [001.undo.log.md](./001.undo.log.md) 的注意事项 1
- 临时表 undo 用 `MTR_LOG_NO_REDO` 不落 redo（`trx0rec.cc:2174-2183`）

## 3. 写入：修改前先记镜像
&nbsp;&nbsp;任何对聚簇索引记录的修改，入口是 `trx/trx0rec.cc:2105 trx_undo_report_row_operation`（调用点 `btr/btr0cur.cc:2607`插入、`:3121/:4278`更新/删除），按操作类型分发：
```cpp
// trx/trx0rec.cc:478   INSERT 镜像: 记录整行内容 (回滚时整行删除)
static ulint trx_undo_page_report_insert(...)
// trx/trx0rec.cc:852   UPDATE/DELETE 镜像: 记录被改列的旧值 + 索引列变化 (回滚时反向更新)
static inline byte *trx_undo_page_report_modify_ext(...)
```
```
执行 UPDATE a=2 (旧值 a=1), trx_id=100:
 ① report_modify: 把 (a=1, 主键, info_bits...) 写入 update undo log ──▶ 得到 roll_ptr
 ② 就地改记录: DB_TRX_ID=100, DB_ROLL_PTR=①          ← 次序不可颠倒
```
> undo 记录的物理格式（TRX_UNDO_INSERT_REC / UPD_REC 的字段布局）概念篇 [001.undo.log.md](./001.undo.log.md) 有图；`DB_ROLL_PTR` 56 位编码见 [MVCC 篇 §2.2](../007.InnoDB之MVCC实现原理(基于8.0.30源码).md)。

## 4. 提交：update undo 不删除，改挂 history list
```cpp
// trx/trx0undo.cc:1798  事务提交时把 undo 头部状态置为 TRX_UNDO_FINISHED
page_t *trx_undo_set_state_at_finish(...)
// trx/trx0purge.cc:317  update undo 从事务侧移交 purge 系统的 history list
void trx_purge_add_update_undo_to_history(...)
```
```
insert undo:  COMMIT ─▶ 状态置 FINISHED ─▶ undo segment 内立即可复用(下一个事务)
update undo:  COMMIT ─▶ 状态置 FINISHED ─▶ 挂入 rseg history list ─▶ 等 purge
              (能否删除由「系统里最老的 ReadView 是否还需要它」决定, 见 004.purge.md)
```
> 什么时候回滚用？什么时候 MVCC 用？——insert undo 只会被回滚用；update undo 两者都可能用。事务在 XA PREPARE 时状态由 `trx0undo.cc:1838 trx_undo_set_state_at_prepare` 管理。

## 5. 回滚：反向执行（逻辑回滚）
&nbsp;&nbsp;回滚不是"把页恢复成事务前的样子"，而是**逐行反向执行**——因为同一页可能还有其他并发事务的修改：
```
trx_rollback_low (trx/trx0roll.cc:180)
   └─▶ row_undo (row/row0undo.cc:247)   沿 undo log 逐条:
         ├─ :158 row_undo_search_clust_to_pcur —— 按主键定位当前记录
         ├─ INSERT 的 undo  ─▶ :296 row_undo_ins   —— 物理删除该行
         └─ UPDATE/DELETE   ─▶ :301 row_undo_mod   —— 反向更新:
                 row_undo_mod_del_mark(回滚删除标记)
                 row_undo_mod_upd_exist_sec(修二级索引)
                 ...子函数位于 row/row0u*.cc
```
```
UPDATE a: 1 ─▶ 2, 回滚:
  undo 记录: {主键P, 旧值 a=1}  ──▶ row_undo_mod: 把 P 行的 a 改回 1, 恢复二级索引
INSERT 新行 P, 回滚:
  undo 记录: {整行}             ──▶ row_undo_ins: 直接把 P 行删掉
```
> 对照：**redo 是物理日志**（页偏移级，重放幂等）；**undo 是逻辑日志**（行级反向操作，回滚后页的二进制布局可能与事务前不同）。

## 6. 页重用与空间
- 提交后 undo 页满足重用条件时可给下一个事务用：`trx0undo.cc:1607 trx_undo_reuse_cached`
- 长事务 → history list 堆积 → undo 表空间膨胀（`trx0sys.h:476 rseg_history_len` 观测），且 MVCC 回溯链变长——详见 [004.purge.md](./004.purge.md) 与 [MVCC 篇 §8](../007.InnoDB之MVCC实现原理(基于8.0.30源码).md)
