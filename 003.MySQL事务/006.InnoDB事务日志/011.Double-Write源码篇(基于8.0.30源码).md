# Double Write 源码篇（基于 MySQL 8.0.30 GA）
&nbsp;&nbsp;**刷脏页前先把整页拷贝到 double write 文件并落盘，再写数据文件——用它解决 partial write（页写了半个就宕机），因为 redo 只能重放"连续正确"的页。**
> 概念篇: [003.Double-Write.md](./003.Double-Write.md) · redo/WAL: [007.预写日志WAL如何提升数据库性能原理](./007.预写日志WAL如何提升数据库性能原理.md) · [008.redo.log源码篇](./008.redo.log源码篇(基于8.0.30源码).md)

## 0. 源码路径约定
&nbsp;&nbsp;`文件:行号` 相对 `001.SOURCE_CODE/001.mysql-server-8.0.30-GA/mysql-8.0.30-server/storage/innobase/`。核心文件：`buf/buf0dblwr.cc`（8.0.20 起的 dblwr v2 新实现，namespace `dblwr::`/`Double_write` 类）、`buf/buf0flu.cc`（刷页入口）。

## 1. 为什么 redo 救不了半个页
```
16KB 页只写到一半宕机(原子性 < 页大小):
 ┌─────────────────────────────┐
 │ 前半: 新内容 ✓   后半: 旧内容/垃圾 │   ← 页本身校验(checksum)已损坏
 └─────────────────────────────┘
 redo 是「页内偏移级的增量」，重放前提是页的初始状态合法；
 页都读不出来，redo 无从重放 → 必须先有一份"损坏前"的完整副本 ⇒ Double Write
```

## 2. 写路径总图
```
 page cleaner 刷脏页
   └─▶ buf_flush_page (buf0flu.cc:1281)
        └─▶ buf_flush_write_block_low (buf0flu.cc:1171)
             ├─ ① WAL 强制点: 先 log_write_up_to(页的最新LSN) (:1207-1222)
             └─ ② dblwr::write (buf0dblwr.cc:2490)  ← dblwr::is_enabled() 才走
                  ├─ Double_write::prepare (:1306)  写前校验
                  │    └─ check_block(:1544)/check_page_lsn(:1515):
                  │       页内 FIL_PAGE_LSN 与页尾 LSN 低4字节一致性检查
                  ├─ 页拷贝进 dblwr 内存批(batch, dblwr 文件段管理)
                  ├─ 批满 / sync 场景 → Double_write::write_pages (:2258)
                  │     ③ 把 dblwr 批整块写到 .dblwr 文件并 fsync   (先)
                  │        [dblwr 文件 = #ib_<页大小>_<序号>.dblwr, 见 §3]
                  │     ④ Double_write::write_data_pages (:2204)
                  │        把数据页写到 .ibd                          (后)
                  └─ 完成回调 dblwr::write_complete (:2622) 清理批状态
```
```
时序(保证):  ③ dblwr 文件落盘 ──▶ ④ 数据文件写页 ──▶ 崩溃?
   · ④ 之前崩: 数据页是旧的完整页, dblwr 里有多余副本 → 无害
   · ④ 中途崩: 数据页半写(损坏) → 启动恢复时用 ③ 中副本覆盖 → 页恢复完整
   即: 任何时刻磁盘上要么旧页完整, 要么新页完整, 要么 dblwr 里有新页完整副本
```
> dblwr 与 WAL 的分工：**WAL/redo 解决"页是旧的"**（可重放推进），**dblwr 解决"页是坏的"**（先恢复完整再重放）。redo 文件自身不需要 dblwr——它按 512 字节扇区块写入，块粒度天然原子。

> **v1 → v2**：8.0.20 之前 dblwr 存放在系统表空间内固定的 2×1MB 区域；8.0.20 起改为数据目录下**独立的 `.dblwr` 文件**（v2，本文源码即此实现，`buf0dblwr.cc` 全文都是新实现），旧区域仅作 v1 兼容（`dblwr::v1::init`，`buf0dblwr.cc:2899`）。

### 3.1 dblwr 文件到底长什么样
&nbsp;&nbsp;**dblwr 文件 = 数据目录（或 `innodb_dblwr_dir` 指定目录）下的 `#ib_<页大小>_<序号>.dblwr`**，文件名由 `dblwr_file_open` 拼接（`buf0dblwr.cc:2662-2668`：`"#ib_" + srv_page_size + "_" + id + ".dblwr"`）：
```
datadir/                              ← innodb_dblwr_dir 未设置时 dblwr::dir="."
                                         (handler/ha_innodb.cc:12891)
├── #ib_16384_0.dblwr                 ← 偶数序号: flush list 批量刷页的落盘区
├── #ib_16384_1.dblwr                 ← 奇数序号: LRU 单页刷的落盘区
├── #ib_16384_2.dblwr                 ← (文件数与 buffer pool 实例数相关)
└── ...
```
| 事实 | 源码 |
|---|---|
| 文件名 `#ib_<页大小>_<id>.dblwr` | `buf0dblwr.cc:2662-2668`（16K 页即 `#ib_16384_0.dblwr`）；`.dblwr` 是 InnoDB 认识的后缀（`fil/fil0fil.cc:291`） |
| 目录默认 = 数据目录；`innodb_dblwr_dir` 指定相对路径时自动加 `#` 前缀 | `handler/ha_innodb.cc:12877-12888` |
| 奇数 ID 文件用于 LRU（单页刷），偶数 ID 文件用于 flush list（批量刷） | `buf0dblwr.cc:141-150`（`File::is_odd()/is_for_lru()`） |
| 每个文件含若干段(segment)，每段 64 页(1MB@16K)：`s_n_pages = dblwr::n_pages × segments_per_file` | `buf0dblwr.cc:82`(`n_pages{64}`)、`:2797` |
| 文件数随 buffer pool 实例数扩展 | `buf0dblwr.cc:78`(`n_files{1}`)、`:2772-2791` |
| 恢复时按正则 `#ib_([0-9]+)_([0-9]+)\.dblwr` 扫描目录、要求序号连续 | `buf0dblwr.cc:3419-3457` |

> 直观理解：`.dblwr` 文件就是一组"固定大小的暂存格"，每格放一个完整的 16KB 页镜像；写数据文件之前先整块 fsync 这些格子。

## 4. 恢复路径：用 dblwr 副本抢救坏页
```
崩溃恢复 (log0recv.cc):
 recv_recovery_from_checkpoint_start (log/log0recv.cc:3845)
   └─ :3827  recv_sys->dblwr->recover()
        ├─ dblwr::recv::load (buf0dblwr.cc:3380)      读入全部 .dblwr 文件的页帧
        │    └─ 对每个副本校验 checksum, 合法的存入 recv::Pages
        ├─ 重放 redo 过程中读某页时:
        │    dblwr::recv::recover (:2626) / dblwr_recover_page (:3023)
        │    └─ 若 .ibd 中该页损坏(校验不过) → 用 dblwr 副本整页覆盖 → 再重放 redo
        └─ dblwr::recv::Pages::recover (:3164) 逐 space 清理/落地
```
```
恢复时间线: 坏页 .ibd ──▶ dblwr 副本(完整) ──▶ 重放 redo(推进到最新) ──▶ 页完好
```

## 5. 成本与参数
- **写放大**：每页刷盘 = dblwr 写一次 + 数据文件写一次（顺序度也不同：dblwr 文件小而连续）。对 SSD 可评估关闭 `innodb_doublewrite=OFF`（需接受 torn page 风险）
- 相关参数：`innodb_doublewrite`（开关）、`innodb_dblwr_dir`（dblwr 文件目录，默认即数据目录，见 §3.1）
- 观测：`SHOW GLOBAL STATUS LIKE 'Innodb_dblwr%'`（`Innodb_dblwr_writes/pages_written`）
