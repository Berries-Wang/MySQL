# MySQL 中，distinct 和 group by 哪个效率更高
## 结论
- 语义相同，有索引的情况下，group by 和 distinct都能使用索引，效率相同。
- 语义相同，无索引的情况下，distinct效率高于group by 。因为distinct 和 group by 都会进行分组操作，但是group by 可能会进行排序，触发filesort,导致sql执行效率低下。

---
## 优化原理（源码视角，基于 8.0.30）
### 架构视角：分组/去重语义在 Server，引擎只能"把行按序送来"
```
有索引:  InnoDB: 按分组键有序的行流 ──跨层──▶ Server: 流式聚合, 不物化 ✓
无索引:  InnoDB: 任意顺序的行流     ──跨层──▶ Server: 全部进临时表(Using temporary)
                                                   → 聚合 → (历史上)再 filesort
```
- 引擎不认识 GROUP BY/DISTINCT 语义；它唯一的"优化姿势"就是让行流天然有序（所以有索引才有质变）
- `Using temporary` 出现 = 数据已经"全部进了 Server"——跨层边界就是成本台阶

### 有索引时：两者都走索引，"分组"由索引序直接给出
```
idx(a) 上 GROUP BY a / SELECT DISTINCT a:
  B+ 树叶子按 a 有序 → 组边界天然可识别 → 跳跃式扫描, 每组只取一行
      (1,1,1,2,2,3) → 读到 1 → 跳到 2 → 跳到 3
      扫描量 ∝ 组数, 而不是行数
```
- `GroupIndexSkipScanIterator`（`sql/range_optimizer/group_index_skip_scan.cc:142` Init）——即松散索引扫描，EXPLAIN 显示 `Using index for group-by`
- 8.0.13+ 的 Skip Scan（`IndexSkipScanIterator`，`sql/range_optimizer/index_skip_scan.cc:125`）：查询条件缺联合索引前缀列时也能跳跃使用索引

### 无索引时：都要物化，差别在"是否多做一次排序"
```
无索引 GROUP BY: 临时表(分组键+聚合值) → 逐行聚合 → (历史上)还要按分组键排序输出 → filesort
无索引 DISTINCT: 临时表(全列+去重)     → 逐行插入去重 → 完成
```
- 那个"可能多做的排序"就是 `filesort`（`sql/filesort.cc:366`）——原文结论的机理出处
- **8.0 的重要变化**：GROUP BY 已不再隐式排序（`ORDER BY NULL` 因此失去意义），8.0 下两者差距比 5.7 时代小；原结论对 5.7 及更早版本最准确
- 共同的成本大头是 `Using temporary`（临时表）→ **无论 distinct 还是 group by，第一优化方向永远是给分组列建（覆盖）索引**
