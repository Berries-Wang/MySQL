# 脏读、幻读、不可重复读
&nbsp;&nbsp;三者都是「并发事务之间互相干扰」的表现形式，只是干扰的方式不同。区别记忆口诀：**脏读读的是没提交的，不可重复读是同一行值变了，幻读是行数变了**。

## 0. 总览：一张图区分三种现象
```
 事务A两次读之间, 事务B做了什么?          A 读到了什么?          现象
─────────────────────────────────────────────────────────────────────
 什么都没做/还没提交, A 却读到了 B      B 未提交的中间数据  →  脏读 Dirty Read
 的修改并读取了它                                        (读到了不该读的)
─────────────────────────────────────────────────────────────────────
 UPDATE 同一行并 COMMIT                同一行两次值不同    →  不可重复读
                                                          Non-Repeatable Read
                                                          (针对"一行", 值变)
─────────────────────────────────────────────────────────────────────
 INSERT(或 DELETE) 并 COMMIT           结果集多出/少了行   →  幻读 Phantom
                                                          (针对"行集合", 行变)
─────────────────────────────────────────────────────────────────────
```

## 1. 脏读（Dirty Read）
> 脏读是指在不同的事务下，当前事务可以读到另外事务**未提交**的数据，这也违反了数据库事务的隔离性。
+ 违反了数据库的隔离性
+ 因为读取到的是未提交的数据，后续的动作尚不可知(提交事务 或 回滚)，所以当前事务读取到的数据可能是脏数据
+ 一个事务一次读取

```
Session A (读)                        Session B (写)
─────────────────────                 ─────────────────────
                                      BEGIN;
                                      UPDATE t SET a=2 WHERE id=1;
                                        ← a: 1→2, 尚未提交
SELECT a FROM t WHERE id=1;
  └─▶ 读到 a=2  ★脏读: B 并未提交
                                      ROLLBACK;
                                        ← a 回到 1, "a=2" 从未存在过
★A 基于 a=2 做的任何后续决策, 都建立在一条"从未被承认"的数据上
```

---

## 2. 不可重复读（Non-Repeatable Read）
> 不可重复读指在一个事务中多次读取到同一数据集合，在这个事务还没有结束时，另外一个事务也访问同一数据集合，并做了一些DML操作，因此，在第一个事务的两次读取之间，由于第二个事务的修改，那么第一个事务两次读取到的数据可能就不是一样的了。这种情况就称为不可重复读。
+ 不可重复读违反了数据库事务的一致性
+ 一个事务，多次读取
+ 脏读与不可重复读的区别: 脏读是读取到未提交的数据，不可重复读是读取到了已提交的数据

```
Session A (读)                        Session B (写)
─────────────────────                 ─────────────────────
BEGIN;
SELECT a FROM t WHERE id=1;
  └─▶ a=1  (第 1 次读)
                                      UPDATE t SET a=2 WHERE id=1;
                                      COMMIT;
                                        ← 已提交, a=2 是"合法"数据
SELECT a FROM t WHERE id=1;
  └─▶ a=2  ★不可重复读: 同一事务内, 同一行两次读取值不同
★与脏读的本质区别: A 两次读到的都是已提交数据;
  问题在于 A 自己的事务里"读着读着数据变了"
```

---

## 3. 幻读（Phantom）
> 幻读指在同一个事务下，连续执行两次同样的SQL语句可能导致不同的结果，第二次执行的SQL语句可能返回之前不存在的行。
+ 幻读违反了数据库的隔离性
+ 一个事务，多次读取
+ 第二次执行的SQL读到之前不存在的行: 即可能在第一次和第二次读取之间被插入了一个新的数据行

```
Session A (读)                        Session B (写)
─────────────────────                 ─────────────────────
BEGIN;
SELECT * FROM t WHERE id>2;
  └─▶ 3,4,5  (3 行)
                                      INSERT INTO t VALUES(7,...);
                                      COMMIT;
SELECT * FROM t WHERE id>2;
  └─▶ 3,4,5,7  ★幻读: 凭空多出一行"幻影行"(Phantom Row)
★与不可重复读的区别:
  不可重复读: 同一"行"的值变了      (UPDATE)
  幻读:       同一"结果集"的行数变了 (INSERT / DELETE)
```

---

## 4. 三者对比
| 维度 | 脏读 | 不可重复读 | 幻读 |
|---|---|---|---|
| 读到的数据 | **未提交**（脏数据） | 已提交 | 已提交 |
| 另一事务的操作 | UPDATE/DELETE（未提交） | UPDATE/DELETE（已提交） | INSERT / DELETE（已提交） |
| 变化的对象 | 数据本身不可靠 | 同一行的**值** | 结果集的**行数** |
| 读取次数 | 一次即可中招 | 同一事务多次读取 | 同一事务多次读取 |
| 违反 | 隔离性 | 一致性 | 隔离性 |

## 5. 隔离级别与三种现象（SQL 标准）
```
 隔离级别                脏读      不可重复读     幻读
 ─────────────────────────────────────────────────────
 READ UNCOMMITTED       可能  ✓    可能  ✓      可能  ✓
 READ COMMITTED         避免       可能  ✓      可能  ✓
 REPEATABLE READ        避免       避免         可能* ✓
 SERIALIZABLE           避免       避免         避免
 ─────────────────────────────────────────────────────
 越往下越严格、并发性能越低; 从下往上逐个"消灭"一种现象
```
> `*` **InnoDB 的特殊之处**：RR 是 InnoDB 默认级别，且通过 MVCC（快照读）+ Next-Key Lock（当前读）在 RR 下已基本避免幻读，达到 SERIALIZABLE 的隔离效果而无需真正串行化。原理与源码见 [007.InnoDB之MVCC实现原理(基于8.0.30源码)](../003.MySQL事务/007.InnoDB之MVCC实现原理(基于8.0.30源码).md)、[001.InnoDB中的事务隔离级别和锁的关系](../003.MySQL事务/001.InnoDB中的事务隔离级别和锁的关系.md)。
