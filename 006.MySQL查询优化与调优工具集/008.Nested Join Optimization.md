# Nested Join Optimization
&nbsp;&nbsp;The syntax of table_factor is extended in comparison with the SQL Standard. The latter accepts only table_reference, not a list of them inside a pair of parentheses. This is a conservative<sup>adj.保守的；保守派的，</sup> extension if we consider each comma in a list of table_reference items as equivalent to an inner join. For example:(与标准SQL相比，table_factor语法得到了拓展：标准SQL只接受单个 table_reference，不支持**括号内以逗号分隔的表引用列表**。如果我们将table_reference项列表中的每个逗号视为内部连接，这是一个保守的扩展。例如:)
```sql
    SELECT * FROM t1 LEFT JOIN (t2, t3, t4)
                 ON (t2.a=t1.a AND t3.b=t1.b AND t4.c=t1.c)

        Is equivalent to:(等价于)

    SELECT * FROM t1 LEFT JOIN (t2 CROSS JOIN t3 CROSS JOIN t4)
                 ON (t2.a=t1.a AND t3.b=t1.b AND t4.c=t1.c)
```
&nbsp;&nbsp;In MySQL, CROSS JOIN is syntactically<sup>adv.依照句法地；在语句构成上</sup> equivalent to INNER JOIN; they can replace each other. In standard SQL, they are not equivalent. INNER JOIN is used with an ON clause; CROSS JOIN<sup>标准SQL中为两个表的笛卡尔积；注意 MySQL 中 CROSS JOIN 与 INNER JOIN 等价、也可带 ON（见上文）</sup> is used otherwise.(在MySQL中，在语法上，CROSS JOIN等价于INNER JOIN，他们能够相互替换。在标准的SQL中，他们是不相等的。INNER JOIN 和ON子句一起使用；CROSS JOIN被用于其他情况)

## 优化原理与源码对照（基于 8.0.30，2026-10-25 增补）

> 全目录总纲见 [README.md](./README.md)。互通: [010.Outer Join Optimization.md](./010.Outer%20Join%20Optimization.md)（外连接转内连接就发生在这棵嵌套连接树上）、[006.Nested-Loop Join Algorithms.md](./006.Nested-Loop%20Join%20Algorithms.md)。

- 本篇是语法层内容，决定的是 **join 树的形状**：括号表列表在解析后形成嵌套连接 nest；外连接消除 `Query_block::simplify_joins`（sql/sql_resolver.cc:1880，消解阶段调用点 :749）遍历的正是这棵树。
- MySQL 中 CROSS JOIN ≡ INNER JOIN 的等价性在解析器层面成立；这为优化器把 `(t2,t3,t4)` 视作内连接链、进而自由重排表序打下基础。
- 标准 SQL 中 CROSS JOIN（无条件的笛卡尔积）与 INNER JOIN 不等价——写跨方言 SQL 时注意。
